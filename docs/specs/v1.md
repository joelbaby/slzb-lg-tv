# LG TV app v1

## Problem
Users should control an LG webOS TV directly from a SMLIGHT SLZB-OS app without Home Assistant, copied credentials, a helper program, or an always-on relay.

## Approved scope
One configurable TV per installation, with Pair, On, Off, and Forget. Pair starts from the app and requires only accepting the TV's approval prompt after normal TV/network configuration. The app receives and privately saves the resulting key. Power-on uses Wake-on-LAN; power-off uses an authenticated webOS command. A clean public GitHub repository, MIT licence, Issues, and PR review provide transparent development.

## User stories and acceptance
1. Configure a TV address and Wi-Fi MAC without modifying source code.
2. Click Pair and see a prompt on the TV.
3. Approve on the TV and see pairing complete without typing or copying a key.
4. Reject, cancel, or time out pairing without replacing a previous valid credential.
5. Reopen the app and retain configuration and pairing.
6. Click On to send a wake packet to the configured TV.
7. Click Off to submit an authenticated power-off command directly from the coordinator.
8. See honest command results; never equate a sent packet with confirmed TV state.
9. Click Forget to remove the local credential and understand that TV-side revocation is separate.
10. Receive useful, secret-free errors for invalid configuration, unavailable TV, failed authorization, or a busy shared HTTP client.
11. Preserve unrelated coordinator scripts and their startup state on success, failure, cancellation, and timeout.
12. Install a versioned ZIP compatible with the official SLZB app format.
13. Keep all credentials and local deployment details out of source control, release archives, browser storage, and logs.

## Implementation decisions
Use a Berry backend and an app page integrated through the official BeApp SDK. Keep configuration and credentials in the app sandbox. Native transport feasibility is unresolved: prior firmware testing showed successful secure WebSocket writes but failed reads after bodyless HTTP 101. No fake Pair success or helper fallback is acceptable. Shared HTTP ownership must be explicitly coordinated; the generic app must not embed one household's lighting logic.

## Agreed test surfaces
Test public app actions and resulting configuration/status, credential lifecycle, shared HTTP failure/recovery behavior, and installer package constraints. Use a controlled TV/transport fixture for reproducible protocol behavior. Live acceptance is a fresh Pair -> Yes on TV -> On/Off sequence on the target MR4U, with original automations restored afterwards. Unsupported hardware or firmware must not be claimed tested.

## Out of scope
Multiple TVs per installation; volume, input selection, or full remote controls; cloud accounts; firmware flashing; Home Assistant dependency; publication to the upstream SMLIGHT app catalog without a separate decision.

## Known release gate
Receiving the new pairing key without additional user steps must be demonstrated before v1 is declared usable. If current firmware cannot support it, publish the evidence and a truthful blocked status rather than substitute a lesser workflow.
